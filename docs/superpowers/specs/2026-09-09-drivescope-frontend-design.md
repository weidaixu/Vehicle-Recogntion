# DriveScope 高级前端迁移设计

## 目标

将现有 Streamlit 展示页迁移为 React + Vite 单页应用，并使用 FastAPI 暴露现有 PyTorch 模型、车型资料、本地图片检索、Wikimedia Commons 检索和 DeepSeek 智能体能力。最终页面应具备独立视觉身份、流畅动效、清楚的工具调用证据和完整的异常反馈。

## 视觉系统

- 背景照片顺时针旋转 90 度，输出横向优化版本，作为首屏全幅背景；桌面端保留车辆在画面左侧，移动端以车辆为焦点重新裁切。
- 色板：夜幕黑 `#141713`、岩土棕 `#4C4538`、雾山灰 `#9C9A90`、车漆银 `#D5D7D2`、尾灯红 `#D92D32`、晨光白 `#F3EEDD`。
- 字体使用现代窄体展示字配合易读中文无衬线正文；数据编号、类别 ID 和置信度使用等宽字体。
- 首屏采用电影式构图，右侧悬浮半透明控制台，不能遮挡背景车辆主体。
- 背景使用 Three.js WebGL 景深场景。旋转后的照片拆分为车辆前景、地面和远山三层，通过透视相机、深度位移和轻量着色器形成真实的空间层次。
- 鼠标、触控和设备方向输入只产生小幅视差，车辆、地面与远山以不同速度移动；页面滚动改变相机位置，不改变照片主体比例。
- 视觉签名为“尾灯扫描线”：上传和推理期间，一条红色扫描光带经过预览图，完成后收束为置信度刻度。
- 环境光从晨光白过渡到尾灯红，卡片边缘根据鼠标位置产生受控的玻璃高光；空闲状态只保留低频呼吸光。

## 页面与交互

- 首页显示产品说明、模型状态、51 类状态、Macro-F1 和 DeepSeek 连接状态。
- 车型识别：拖放或选择图片、预览、开始识别、Top-3、置信度、unknown 与低置信度提示。
- 车型资料：按 ID 或车型名搜索，读取 `class_info.json` 展示名称和类型。
- 设计语言：将识别结果、车型资料和用户问题交给 DeepSeek-V4-Flash，生成包含车身比例、灯组、曲面、空气动力学、品牌特征和设计风格的结构化分析。
- 多视角视觉档案：优先从本地该类别训练与验证图片中检索多张代表图，再从 Wikimedia Commons 补充公开授权素材；每张网络图片展示作者、许可证和来源链接。
- 设计板：将识别结果、设计语言、多视角图片和来源署名排成可下载的汽车设计研究板；网络检索失败时仍可使用本地图片完成。
- 智能对话：保留同一会话的识别上下文，支持“识别这辆车、分析设计语言并生成视觉档案”的连续任务。
- 工具轨迹：按时间显示 `classify_car`、`query_car_info`、`generate_design_language`、`search_vehicle_views` 和 `build_design_board` 的真实调用、参数、状态和结果。
- 首次进入从高速径向模糊过渡到车辆定格，随后出现赛车 HUD 刻度和系统状态；动画完成后不循环播放。
- 动效包含背景三层视差、面板弹性切换、按钮磁吸悬停、扫描光带、结果卡片进入和工具链脉冲连线。
- 点击识别时，HUD 速度刻度短暂加速、红色扫描框锁定图片，结果返回后光效收束到置信度读数。
- 遵守 `prefers-reduced-motion`；低性能或不支持 WebGL 的设备自动切换为静态背景、无视差和淡入过渡。

## 技术架构

- `frontend/`：React、TypeScript、Vite、Framer Motion、Three.js 与 React Three Fiber；使用原生 CSS 变量维护主题，不引入重型 UI 套件。
- 3D 场景与业务组件隔离：背景画布只接收指针位置、滚动进度和识别状态，不读取模型结果或 API Key。
- `backend/`：FastAPI，复用 `VehicleClassifier`，新增设计语言、多视角检索和设计板服务；API Key 仅从后端环境变量读取。
- 静态资源：旋转后的背景图放在 `frontend/public/assets/hero-car.jpg`，保留原图不修改。
- 后端接口：
  - `GET /api/status` 返回模型、类别、指标和 DeepSeek 配置状态。
  - `POST /api/classify` 接收图片和阈值，返回标签、置信度、Top-3 与拒识状态。
  - `GET /api/cars` 支持车型搜索；`GET /api/cars/{id}` 返回车型资料。
  - `POST /api/design-language` 调用 DeepSeek 返回结构化设计分析。
  - `GET /api/vehicle-views/{id}` 检索本地图片和 Wikimedia Commons 开放素材，并返回来源元数据。
  - `POST /api/design-board` 生成可下载的视觉档案设计板。
  - `POST /api/agent` 接收 session ID、文本和可选图片，执行连续工具调用并返回回答与工具轨迹。
- 开发环境由 Vite 代理 `/api` 到 FastAPI；生产构建可由 FastAPI 托管静态文件。

## 错误处理与安全

- 图片格式、大小或解码失败返回明确的 4xx 错误；模型和 DeepSeek 故障返回可理解提示。
- DeepSeek API Key 不进入前端包、日志或接口响应；Wikimedia Commons 使用无需密钥的公开接口。
- 网络素材只接受具有明确许可证信息的条目；界面和设计板均保留作者、许可证、原始文件页和修改说明。
- 所有工具结果保留 `ok`、错误信息和调用 ID；前端不把失败状态展示为成功。
- 上传图片只用于当前识别请求，不默认持久化。

## 验收标准

- 桌面和移动视口均无溢出、遮挡或不可读文本。
- 背景图方向正确，主题配色与照片一致，车辆主体在首屏可见。
- 支持 WebGL 时可以观察到车辆、地面与远山的分层视差；关闭 WebGL 或启用减少动态效果后仍能正常使用所有功能。
- 识别时赛车 HUD、扫描框和光效状态与请求开始、成功或失败同步，不出现无限加载动画。
- 车型识别、设计语言生成、多视角视觉档案三项核心功能都调用真实后端并显示结果。
- 上传教师数据中的图片后能完成视觉推理，不再出现 `UploadedFile.convert` 错误。
- 连续任务可显示 `classify_car → query_car_info → generate_design_language → search_vehicle_views → build_design_board` 的真实执行顺序。
- 视觉档案在网络不可用时自动使用本地数据集图片；有网络素材时必须展示可核对的许可证和来源链接。
- 设计板可下载，包含车型、设计语言、多视角图片和素材署名；会话内识别上下文可继续使用。
- 前端构建、后端测试、API 集成测试和浏览器视觉交互检查全部通过。

## 默认决策

- 保留现有 Streamlit 文件作为回退入口，但最终展示默认使用 React 页面。
- 第一版不增加用户账号和收藏系统，重点完成识别、设计语言、视觉档案和设计板导出。
- 动效强调识别过程，不使用持续干扰阅读的粒子或循环动画。
- “3D 背景”定义为基于原照片的 WebGL 深度分层与视差，不生成或替换照片中的车型，不引入需要下载的大型三维车辆模型。
- 当前轻量 CNN 模型继续作为可运行基线；模型精度优化与前端迁移解耦。
